# PocketHero — Дизайн-документ (GDD v0.1)

*Дата: 2026-06-05. Статус: чернетка на ревʼю режисера. Усі числові значення нижче — **пропозиції-дефолти**, позначені 🎚️, їх правимо вільно.*

---

## 1. Суть і стовпи

**PocketHero** — веб ідл-автобатлер у фентезі-сетингу, «My Brute на максималках». Гравець вирощує унікального героя, **зліплюючи його з пікселів**, і той бʼється з героями інших гравців асинхронно.

Сім стовпів (від режисера):

1. **Асинхронне ММО** — персистентний світ, бої проти снапшотів чужих героїв, ладдери.
2. **Шлях у Steam** — лишаємось портабельними (веб, обгортабельний у Tauri/Electron).
3. **Easy to learn / hard to master** — глибина з білду й форми, не з реакції.
4. **Вау-моменти** в бою — заряджені техніки, криті, ланцюги, відколювання пікселів.
5. **Збалансований рандом** — hit / dodge / crit / block у формулі, але на детермінованому сіді.
6. **Грати фоном, завжди є що гріндити** — офлайн-прогрес, кілька осей грінду, бій можна дивитись або інстант-резолвити.
7. **Фентезі + магія** — типи пікселів виходять за фізику (вогонь/лід/блискавка, мана, підсилювачі).

### Не-цілі v1 (YAGNI)
- Тактика-«мозок» героя (модель А) — **потім**; v1 = чистий авто (модель Б).
- Монетизація, клани/гільдії, реал-тайм будь-що, кросплатформ-акаунти.

---

## 2. Кор-луп

```
Бій (авто) → XP + матеріали → рівень → +1 піксель → ліпиш у білд →
сильніший/інакший герой → вищий ладдер → складніші вороги → ...
```

- **Активна сесія:** дивишся бій (juice!), перебудовуєш героя, лізеш у ладдер, виконуєш дейлі.
- **Фонова/офлайн:** герой авто-гріндить PvE-ладдер, копить XP+матеріали (з кепом), повертаєшся — є що розкласти.

---

## 3. Герой і пікселі

### Ріст
- Старт: **1 піксель** (Ядро).
- Кожен рівень: **+1 піксель** на вибір типу (з відкритих), ліпиш на сітку **куди хочеш** (суміжно до існуючих).
- **Респек:** пікселі можна пересувати/міняти за `Shards` 🎚️ — заохочуємо експерименти (easy to learn).

### Типи пікселів (ростер v1) 🎚️
| Піксель | Колір | Ефект |
|---|---|---|
| **Ядро** (Core) | жовтий | Серце. Рівно 1 шт. Знищене → смерть. **Вразлива точка** (див. форму). |
| **Vital** | зелений | +HP |
| **Force** | червоний | +фіз. атака |
| **Plate** | синій | +броня (флат-зниження урону) |
| **Swift** | бірюзовий | +ініціатива (частота ходів) і +шанс доджу |
| **Focus** | білий | +шанс криту і +точність |
| **Ember/Frost/Spark** | вогонь/лід/іскра | магічна атака стихії |
| **Mana** | синьо-фіолет | паливо для заклять (без мани магія-техніки не працюють) |
| **Catalyst** | магента | підсилює суміжні магічні пікселі |

### Форма має значення (точково)
- **Захист Ядра:** Ядро відкрите ззовні = скляна гармата (легко добити). Закопане + обкладене Plate = танк. → форма впливає на виживання **емерджентно**, без повної фізики.
- **Спец-пікселі в патернах = техніки** (розділ 5).

## 4. Бойова система (хребет проєкту)

### 4.1 Детермінована симуляція
- Бій — **чиста детермінована симуляція на сіді** (`seed + build_A + build_B → той самий результат завжди`).
- Рушій бою — **окремий модуль без залежностей від рендеру** (працює і в браузері, і headless у Node на сервері).
- Наслідки: сервер валідує/реплеїть бій (анти-чит), клієнт може **дивитись АБО інстант-резолвити** (та сама симуляція, різний фронт).

### 4.2 Модель ходу
- **ATB-гейдж** 🎚️: у кожного героя шкала ініціативи, наповнюється від `Swift`. Заповнилась → герой діє.
- Дія = базова атака або готова техніка (пріоритет техніки, якщо умова виконана — модель Б, без вводу гравця у PvP).
- У **PvE** гравець може вручну тригернути активну техніку (єдина «ручна» точка v1).

### 4.3 Формула резолву (дефолти 🎚️)
```
hitChance = clamp(0.75 + accuracy_attacker − dodge_defender, 0.05, 0.99)
  roll > hitChance        → MISS / DODGE  (vfx промаху)
crit      = roll_crit < critChance_attacker
damage    = max(1, atkPower − armor_defender) × (crit ? 1.75 : 1)
            (магічний урон ріжеться mag-резистом, не бронею)
death     = Ядро знищене  OR  HP ≤ 0
```
- `accuracy/crit` ← Focus; `dodge/initiative` ← Swift; `armor` ← Plate; `HP` ← Vital; `atkPower` ← Force/стихії.
- Рандом є (роли), але сід фіксований → азарт без реролів.

### 4.4 Поведінка героя (v1 = модель Б)
- Жодного скриптингу. Простий вшитий ШІ: рухатись до цілі → бити в радіусі → юзати готову техніку коли її умова справдилась.
- Розширення (модель А, потім): гравець задає пріоритети-правила.

## 5. Техніки (рецепти-патерни)

- Технік набір **заздалегідь заданий нами**; гравець їх **відкриває**, склавши спец-пікселі у форму-рецепт.
- Приклади v1 🎚️:
  - **Випад** — 3× Force у лінію назовні → ривок із дальнім reach + нокбек.
  - **Бастіон** — Plate у замкнене кільце → періодичний блок/щит.
  - **Ухил** — симетричні Swift по флангах → сплеск доджу + репозиція.
  - **Вогняна куля** — кластер Ember + суміжна Mana → дальній магічний бурст (вау-VFX).
- Це і є «hard to master»: відкриття синергій і компактна укладка кількох рецептів у одному тілі.

---

## 6. Магія (вісь глибини + VFX)

- Магічні пікселі (Ember/Frost/Spark) дають стихійний урон; **Mana** — обовʼязкове паливо; **Catalyst** підсилює суміжні.
- Стихії → статуси 🎚️: Ember=підпал(dot), Frost=сповільнення ініціативи, Spark=ланцюг по сусідах.
- Магія = найсоковитіші вау-моменти (екранні заклинання).

---

## 7. Прогресія та ідл

- **XP** з боїв → рівні → пікселі (головна вісь).
- **Офлайн-авто-бій:** поки тебе нема, герой фармить PvE-ладдер, копить XP+матеріали з **кепом** 🎚️ (~8–12 год), щоб повернення завжди давало «є що розкласти».
- **Осі грінду:** рівні/пікселі · матеріали (магія/крафт) · розблок технік · ранг-ладдер · дейлі-цілі.
- **Валюти 🎚️:** XP, Shards (респек/реролл), Essence (магія).

---

## 8. Асинхронне ММО

- Будь-яка значуща зміна білду → аплоад **снапшота** героя на сервер (білд+стати+косметика).
- **PvP:** матчмейкінг за рейтингом (MMR/Elo) → тягнемо снапшот опонента → детермінована симуляція на спільному сіді → результат → апдейт MMR → реплей можна подивитись.
- **Анти-чит:** сервер авторитетно ре-симулює бій із сіда+білдів, не довіряючи клієнту.
- Ладдери/лідерборди. (Глобальні асинх-події/боси — потім.)

---

## 9. Візуал та анімація

- **2.5D біллборд (зафіксовано):** пласкі піксель-арт істоти на обʼємній арені; рух/нокбек у глибину, тіні, масштаб за глибиною.
- **Процедурна анімація:** soft-body на пружинах (per-pixel jiggle), дихання, замах, здригання, розсип при смерті — усе кодом (PoC це довів).
- **Juice:** screenshake, hit-stop, спалахи/тінт, цифри урону, відлітаючі пікселі, VFX технік.
- **Drawn-арт мінімальний:** кілька арен + UI-рамки (можна ШІ-ген + дочистка). Персонажів **не малюємо** — їх ліпить гравець.

---

## 10. Технічна архітектура

- **Клієнт:** PixiJS (WebGL 2D) рендер + спільний модуль бойової симуляції.
- **Бойовий рушій:** чистий, детермінований, headless-здатний модуль (TS) — **спільний код клієнта й сервера** → гарантія детермінізму + легко тестувати.
- **Сервер:** Node/TS (та сама мова → той самий sim-код). Зберігає героїв, MMR, ладдери. БД 🎚️ Postgres (або SQLite на старті).
- **Steam-шлях:** Tauri-обгортка поверх веб-білда — без переписування.

---

## 11. Дорожня карта (slices)

1. **Бойовий рушій (headless, детермінований)** + 2.5D Pixi-рендер, щоб дивитись. Два захардкоджені білди бʼються. Де-ризикує філ + закладає хребет детермінізму.
2. **Конструктор** — сітка, ліпиш пікселі, типи→стати, локальне збереження.
3. **Ідл/прогрес** — XP, рівні→пікселі, офлайн-авто-бій vs PvE-ладдер, інстант-резолв.
4. **Техніки-рецепти + магія + вау-VFX**.
5. **Бек + асинх-PvP** — снапшоти, MMR, серверна валідація, ладдер, реплеї.
6. **Поліш, баланс-пас, Tauri/Steam-пакет**.
